This is a **plan, not proof of implementation**. Ranks represent likely *near/midterm usable impact*, considering performance gain, confidence, dependencies and deliverability—not a claim that low-priority modes are unimportant. **Effort** is a relative engineering estimate: S = focused change; M = one subsystem; L = cross-cutting/retraining; XL = new complex decoder. Every proposed improvement must be validated independently; the outside review's numerical speedup and decode-time predictions have not been measured.

## Baseline evidence and release rule

- Active CV detector: held-out IoU 0.5 recall **25.0% live (12/48)** versus **87.1% synthetic (54/62)**; multiple-signal recall **41.2% (28/68)** versus single-signal **90.5% (38/42)**. Small real holdout, but a decisive domain-gap warning.
- The refreshed 199-example classifier improves top-one ranking on a 36-example reference set, but its hierarchical calibration remains `reject_all_no_threshold_meets_validation_constraints` with threshold `1.000001`. **Ranking is not verified identity.**
- Native modes **already implemented** under `sigid/libsigdecode/`: CW, RTTY/ITA2, BPSK31/Varicode, Bell 202 AX.25 UI/FCS. Cross-window evidence streams mostly deduplicate completed outputs; they do not retain continuous demodulator symbol state.
- New detector training was blocked by ROCm initialization crashes and a resource-intensive CPU attempt; no newly trained detector is active. ROCm remediation or a separate stable training worker is a deployment dependency.
- Prior fixes already present *in this branch*: bounded asynchronous review-clip persistence, direct-seek saved WAV waterfalls, capture overrun status, bounded live candidate history. Do **not** repeat them as unimplemented work.
- **Release gate:** keep existing model/preview unchanged until a candidate passes fixed independent source-lineage real and synthetic test splits. Report IoU 0.25/0.50 precision/recall, false detections/audio-hour, frequency MAE, per-mode top-3 recall, abstention, *correct payloads* and wrong-but-readable payloads, P95 CPU/wall latency, and 30-minute capture health. Test is never used to choose thresholds.

## Groundwork: necessary to make impact measurable (G0)

**G0 — End-to-end replay / A-B benchmark (M, dependency of 1–8).** Extend `sigid/conformance.py`, `sigid/cv_flow_evaluation.py`, `sigid/detection_evaluation.py` and `tools/` to replay identical source-lineage-held-out *real* and synthetic PCM through detector → stable track → classifier ranking → acquisition → decoder → UI evidence. Partition real recordings by **session / transmitter/source lineage**, not individual 10-second derived clips. Include silence, HF receiver noise, bad AGC, passband tilt, interference, simultaneous signals, frequency offsets, cropped bursts and −10/−5/0/+10 dB examples. Record exact/partial/wrong/abstain, CRC-verified frame recall, false positive/hour, CPU and drop/queue counters; seed synthetic fixtures; pin artifact hashes. Use a known-good baseline run before changing preprocessing or model weights.

### Corrected / superseded claims in the outside review

1. **"CV detections are untracked" — outdated.** `/api/live/cv-detections` *already* constructs its own namespaced `LiveTrackRegistry` (`api.py:1765-1780`), separate from the heuristic registry. The remaining work is **fusion, identity consistency and better assignment**, not introducing CV track IDs.
2. **"`libsigdecode` is a placeholder" — outdated.** The repo already has native CW, RTTY, BPSK31 and AX.25 UI/FCS decoders. Improve continuous acquisition and verify existing modes before reinventing those decoders.
3. **"All auto trials ignore classifier output and hardcode 3 modes" — partly inaccurate.** `api.py:1923,2199` passes a classifier-generated `decoder_shortlist`; `queue_live_mode_sweep` nevertheless restricts it to three validated Fldigi modes (`api.py:1217-1226`). Its **~2 s crop** and **reject-all classifier gate** remain blockers.
4. **"Fldigi always cold-boots every automatic trial" — conflated paths.** The *isolated replay* explicitly starts Fldigi/Xvfb/PulseAudio per attempt. `FldigiTrialRunner` is initialized with an existing Fldigi client. Optimize the isolated path separately.
5. **"Classifier cache never stores results" — incorrect in this API.** `_classify_signal_crop` prepends `available: True` (`api.py:122-145`) before `LiveClassifierEvidenceCache.remember` (`api.py:1871-1883`). The cache has potential stale-abstention and session-transition issues, but not the claimed missing `available` key.
6. **"Simply widen 10 s live analysis ring to 60 s" — incomplete.** A sixfold snapshot copy per poll would worsen latency. Separate replay history from the bounded detector analysis window first.
7. **"Lower peak spacing to detect FT8/WSPR sub-bin tones" — insufficient.** At 48 kHz/4096 FFT (~11.7 Hz/bin), 6.25 Hz FT8 and 1.46 Hz WSPR tone spacing cannot be separated just by changing the number of suppressed bins. Add a higher-resolution or mode-specific transform.
8. **"10–30x STFT/vectorization", "45–60 s isolated trial", "RSID <50 ms", "100% carrier invariance" — predictions, NOT demonstrated outcomes.** Benchmark timing, CPU, actual generalization and negative-control rejection instead of committing to those speedups.
9. **Completed work should stay completed.** This worktree already includes prior review-writer decoupling, a direct-seek saved WAV waterfall, stopped-capture warnings, simultaneous-scene generation and preview-only classifier deployment. Preserve and regression-test instead of re-queuing.

## Execution order / proposed issues

The ranked table is impact-oriented, but implementation has dependencies. Recommended issue slices:

**Wave A — quick, measurable safety/perf gains (small parallel branches, no model activation):**
- **A1:** G0 baseline runner + golden live, synthetic, noisy, multi-signal manifests.
- **A2:** Fix live partial-window noise estimation; independent tests for active tail + noise-only prefix.
- **A3:** Fix `embed_image` RGB/BGR symmetry, version embedding index; golden image parity tests.
- **A4:** Vectorize CV resize/STFT with exact pixel equivalence *before* v3 preprocessing.
- **A5:** Correct auto trial's 2-second span and premature text acceptance; staged offline queue tests.
- **A6:** Paginate indexed review queue, test 10k clips and stale-result handling.

**Wave B — meaningful live accuracy (dependent on A1/A2/A4):**
- **B1:** CV v3 robust floor + physically valid augmentation + train/retrain/evaluate. Keep old model and independent test frozen; solve GPU training outside capture host if needed.
- **B2:** Classifier relative-frequency / timing v5 and source-lineage holdout.
- **B3:** Conditional calibrated in-family experts + explicit noise/OOD handling; calibrate vs held-out real negative controls.
- **B4:** Multi-resolution CFAR/blob baseline and fused track identities, compare against CV-only.

**Wave C — reliable first-party decoding:**
- **C1:** Persistent per-track streaming decoder interface with bounded soft symbols and frame state.
- **C2:** Shift-aware RTTY, AFC/clock BPSK31, continuous CW, incremental AX.25 framing.
- **C3:** Better CPU trial fairness, exact/partial/wrong evidence grade, frequency-aware candidate shortlist, APRS and RSID.
- **C4:** Separate slotted modem/WSJT-X path after durable 30–60 s replay history exists.

**Wave D — broaden catalog + polish:**
- **D1:** Simplified Monitor/Inspect/Decode/Review with advanced workbench preserved.
- **D2:** Measured warm isolated Fldigi fallback.
- **D3:** PSK63 → QPSK31 → MFSK/Olivia → FT8/FT4/WSPR, each individually tested and separately deployable.

## Hard acceptance / rollout requirements

- Zero silent signal loss in 30-minute capture and unattended mode; expose writer/review backlog, dropped review windows, P95 API/CV latency, decoder busy/budget counters.
- No false *confirmed* identities: model predictions are *hypotheses*; RTTY/CW/PSK printable text is *unverified*; AX.25 packets with passing FCS or protocol-defined integrity can be shown as integrity-checked; human-reviewed label remains a separate source.
- Never choose thresholds on the same held-out test split used to claim improvement. Source-family/session partitioning must prevent repeated 10 s windows and derived clips crossing the split.
- Version any model input feature shape, spectrogram preprocessing, embedding preprocessing, decoder evidence schema, and maintain one-click rollback to the existing active models.
- Native and fallback decoders stay receive-only, sandboxed, bounded and separated from the audio callback. No hardware tests or production service restarts implied by this backlog.
- **Do not implement all rows as one giant PR.** Each wave slice is an issue-ready change with a tiny isolated branch, independent tests, and baseline comparison.
