# AX.25 UI over Bell 202 — evidence dossier

- Owned mode ID: ax25
- Implementation/version: sigid/libsigdecode/ax25.py, ax25-bell202-ui-v1
- State: experimental_implemented; never validated on air (synthetic tests only)
- Primary published protocol specification and exact revision: [TAPR AX.25 v2.2, July 1998](https://files.tapr.org/tech_docs/AX25/AX25.2.2.pdf) (link-layer framing, addresses, control/PID, X.25 FCS). Bell 202 tone/baud parameters (1200 baud, mark 1200 Hz, space 2200 Hz) are modem parameters referenced by, but not fully specified in, that document.
- Protocol fields not yet specified: digipeater C/H-bit handling beyond address passthrough; non-UI frame types (I, S, U other than UI); PID values other than 0xF0; extended/VIA address edge cases; transmitter pre-emphasis/equalization behavior.
- Source/provenance and license audit: independent implementation from the public TAPR document; no OnAir/Fldigi/WSJT-X code or tables copied or translated. DSP uses only NumPy.
- Input: mono audio only, sample rate >= 8000 Hz, >= 0.125 s window; only the first 8 s are processed (bounded CPU). `carrier_hz` is accepted and ignored: Bell 202 energy lives at both tones, not at a single CW-style carrier.
- Output: a frame with exact information bytes (status `decoded`) only with a valid X.25 FCS; otherwise `no_decode` with empty text. Printable ASCII bytes are preserved in the legacy text field and nonprintable bytes render as replacement characters; `frame_hex`/`info_hex` remain byte-exact. Evidence carries frame addresses, sample extents, and the FCS outcome (`fcs_ok`, received/computed hex); failures report `inter_flag_candidates`, `fcs_failures`, and `structural_rejects`.

## Independently generated golden vectors

Fixture encoder lives in tests/test_decode_ax25.py and shares no code with
the decoder (own FCS, stuffing, NRZI, and phase-continuous 2-FSK
implementation, fixed RNG seed 20261122):

- `HELLO WORLD` from N0CALL to APRS at 12000 Hz + noise (std 0.004), and
  `>TEST:123 de N0CALL` at 48000 Hz: decode asserts exact text, FCS-valid
  evidence, addresses `["APRS-0", "N0CALL-0"]`, control `0x03`, PID `0xF0`,
  `info_hex` round-trip, one token with in-window sample extents, and
  `source == sigid-independent-implementation`.
- A valid FCS-protected frame with binary information bytes verifies the raw
  frame payload remains intact while the compatibility text view is safe.
- Both decoder and fixture FCS implementations return the CRC-16/X-25 check
  value `0x906E` for `b"123456789"`; the waveform fixture serializes the FCS
  most-significant bit first as specified in TAPR section 3.8.

## Negative and boundary controls

All must abstain (`no_decode`, empty text): digital silence; white noise
(std 0.05); a frame whose FCS was computed over uncorrupted bytes while one
info bit was flipped (asserts `fcs_failures >= 1`); a structurally
FCS-consistent frame with lowercase callsign bytes (asserts zero FCS
failures, i.e. rejection is by address validation, not luck); wrong tones
(1700/2500 Hz at 1200 baud); wrong speed (1200/2200 Hz at 2400 baud);
sub-0.125 s windows; sample rates below 8000 Hz.

## Reviewed real recordings

None. No over-the-air claim is made; the decoder stays `experimental`
until independently hand-verified Bell 202 captures with packet ground
truth are reviewed.

## Reproducibility and limitations

- Tests: `python -m pytest -q tests/test_decode_ax25.py` (9 tests) and
  `python -m pytest -q tests/test_decoder_contract_docs.py`.
- Known limits: UI frames with control 0x03 / PID 0xF0 and 1+ printable
  ASCII info bytes only (0x20-0x7E); longer windows truncated to the first
  8 s; four fixed quarter-bit timing hypotheses, no Doppler/drift tracking;
  NRZI polarity assumed per TAPR (0 = tone change); weak-signal and
  multi-station performance unmeasured.
- AFSK/HDLC helpers are private to sigid/libsigdecode/ax25.py (names
  underscore-prefixed, no shared imports). The queue lists
  `shared_afsk_hdlc` as an integrator-owned dependency: propose promoting
  these helpers to a common component in a separate integration PR with its
  own generic test case and owner; do not import them from other modes yet.
- Mode is registered as experimental; it is not exposed in the current UI
  menu, and no on-air accuracy is claimed.
- Owner: AX.25 slice worker; reviewer/next gate: coordinator review, then
  real-capture benchmarking before any status above experimental.
